# PP 调度图实现计划

> 执行方式：在当前会话内按 executing-plans 和测试先行流程实现。用户已授权修改后验证、提交、推送并验收 Pages。

**Goal:** 在现有两个标签右侧新增 PP 调度图，按 GBS、MBS、DP 自动计算 MBN，支持 1F1B 与 GPipe 切换。

**Architecture:** 继续保持单 HTML。新增独立的纯调度模型脚本和界面脚本，仅通过配置更新及标签切换接入现有页面。调度按本 stage 串行顺序、前向上游依赖和反向下游依赖计算最早开始时刻。

**Tech Stack:** 原生 JavaScript、CSS、SVG；Node 模型测试、Playwright 浏览器测试，无页面外部运行依赖。

**Spec:** 本文的需求与边界来自本次用户请求及其对调度方式、MBN 口径的明确答复。

## 需求与边界

- 标签顺序：权重切分图、通信组表、PP 调度图。
- MBN = GBS ÷（MBS × DP），PP 和 DP 来自当前左侧配置。
- 支持非交错、同步 flush 的 1F1B 与 GPipe；默认 1F1B，GBS 32、MBS 2。
- 时间横向，stage 纵向；前向蓝绿、反向橙色、空闲浅灰，块内 F/B 后接从 1 开始的微批编号。
- F、B 均按 1 个相对时间步计算，各 stage 等时，不计通信与实际层数造成的时间差异，不预测真实训练性能。
- 拒绝空值、非正整数、非整除及不安全整数；不静默取整。PP × MBN 超过 65,536 时提示减小配置，避免占满浏览器资源。
- 图随 PP/DP/GBS/MBS/模式更新；无效配置立即清除旧图。
- 大图按滚动视窗绘制，保留完整调度数据；提供时间缩放、微批选择和详情。
- 保留原有权重切分、通信组、配置导入导出和 SVG 下载行为；在调度页下载 SVG 对应调度图。
- 新增文档与测试不写入个人绝对路径、旧服务器地址或凭据。

## 设计

沿用原页面白底、深蓝文字和等宽数字；前向 #187f96，反向 #d08a25，空闲 #eef3f7，网格 #dce5ed。标签下显示一行批量输入、计算公式与模式选择，下方是紧凑指标和带固定坐标轴的时间网格。调度视图收起原模块详情栏，为时间轴提供空间；切回原视图时恢复其状态。

## Review Focus

- 多 stage、少微批和 PP=1 均不能死锁或违反计算依赖。
- 不整除、溢出和无效拓扑不能保留看似有效的旧调度。
- 大配置不能按总格数创建海量 DOM；滚动后仍显示正确 stage 与时间。
- 新视图隐藏原通信工具栏与详情，但不能破坏返回后的选择和操作。
- 模式切换、导入导出和新旧 SVG 下载保持一致。

## 调度依据

- [Megatron 非交错流水线调度实现](https://github.com/NVIDIA/Megatron-LM/blob/main/megatron/core/pipeline_parallel/schedules.py)：warmup 后按 forward/backward 交替，最后排空。
- [GPipe 论文](https://arxiv.org/abs/1811.06965)：分微批执行前向与反向的流水线训练。
